ONE App

One platform for every department, layered on the company's ERP — one login, one codebase, two legal entities, six live modules.
The ERP contract. The ERP database is strictly read-only — SELECT with NOLOCK, never a write. Everything the organisation authors itself lives in a writable companion database, with an audit stamp on every row.

Request lifecycle

every call passes through these
1

JWT login

Signed token carries role + company codes · 8 h, or 30 d with remember-me · offline login caches a PBKDF2 hash so field staff can sign in without signal

auth.js · login.js
2

Company resolution

?company= → X-Company header → default · one route file serves two entities with their own currency, locale and ERP table prefix

shared/company.js
3

Role + scope

Role buckets (full access · heads · sales · HR · FAE · warehouse · store) · a user's salesperson codes become an IN(...) clause · no codes → sees nothing

auth.js · shared/roleScope.js
4

Module router

11 department routers under /api/<dept> · HR alone fans out to 27 sub-routers · every /:id route guarded against non-numeric ids

modules/*/index.js
5

Two pools

ERP pool: READ UNCOMMITTED, SELECT only · App pool: read/write with CreatedBy / UpdatedBy stamps · cross-DB joins collated explicitly

db.js · core/middleware/audit.js
6

Response

{rows, totals, currency, symbol, company} · window functions on paged queries so stat cards reflect the full filtered set, not the visible page

res.json · 401/403 → auto-logout

The human's whole job by role

  • Field rep: sign in once; visits are detected, punches are selfies, tomorrow is planned.
  • Sales head: dashboard → outstanding → one-click reminder → payment advice arrives on its own.
  • HR: review anomalies, approve leave, run payroll, issue the letter.
  • Warehouse: ASN wizard → mark received → stock updates itself.
